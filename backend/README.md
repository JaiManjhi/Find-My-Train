# Find My Train — Backend

FastAPI service that used to live inside the Next.js app as `src/app/api/*`
route handlers. Same endpoints, same response shapes — now a standalone API.

See the [repo-level README](../README.md) for the full-stack overview, and
[`../frontend/README.md`](../frontend/README.md) for the UI that talks to
this service.

## Tech Stack

| Technology | Version | Purpose |
|---|---|---|
| [FastAPI](https://fastapi.tiangolo.com/) | 0.115 | HTTP API framework |
| [Python](https://www.python.org/) | 3.11+ | Runtime |
| [Pydantic](https://docs.pydantic.dev/) | 2.10 | Data models & validation |
| [pydantic-settings](https://docs.pydantic.dev/latest/concepts/pydantic_settings/) | 2.7 | Env-var driven configuration |
| [httpx](https://www.python-httpx.org/) | 0.28 | Async HTTP client for upstream APIs |
| [uvicorn](https://www.uvicorn.org/) | 0.34 | ASGI server |

## Structure

```
backend/
├── app/
│   ├── core/
│   │   └── config.py           # Settings: env vars, CORS origin list
│   ├── models/
│   │   ├── train.py            # Station, Train domain models
│   │   └── misc.py             # WeatherData, Attraction, ElevationPoint, SearchResult
│   ├── schemas/                # API-facing request/response shapes (per route group)
│   │   ├── train.py
│   │   ├── weather.py
│   │   ├── elevation.py
│   │   └── places.py
│   ├── repositories/
│   │   ├── train_repository.py # static train DB, route builder, search
│   │   ├── mock_repository.py  # mock weather / attractions / elevation fallback data
│   │   └── data/*.json         # static data, generated 1:1 from frontend/src/data/*.ts
│   ├── services/                # business logic + external API calls
│   │   ├── railradar_service.py    # live train status (+ dynamic fallback positioning)
│   │   ├── weather_service.py      # OpenWeather
│   │   ├── elevation_service.py    # OpenTopography
│   │   └── places_service.py       # Overpass API (OSM landmarks)
│   ├── routes/                  # FastAPI routers, one per resource
│   │   ├── trains.py
│   │   ├── weather.py
│   │   ├── elevation.py
│   │   └── places.py
│   ├── utils/
│   │   └── cache.py             # minimal in-memory TTL cache
│   └── main.py                  # app entrypoint, CORS, router registration
├── requirements.txt
├── .env.example                 # template — copy to .env and fill in your keys
└── README.md                    # you are here
```

Request flow: `routes/` (HTTP layer, query params) → `services/` (business
logic, calls upstream APIs, builds the response shape the frontend expects)
→ `repositories/` (static data + fallback data used when a service call
fails). `models/` and `schemas/` define the Pydantic shapes used throughout.

## Setup & Run

### Prerequisites

- **Python** 3.11+

### 1. Create a virtual environment and install dependencies

```bash
cd backend
python -m venv .venv
.venv/Scripts/activate   # or: source .venv/bin/activate on macOS/Linux
pip install -r requirements.txt
```

### 2. Configure environment variables

```bash
cp .env.example .env
```

Then open `.env` and fill in your own API keys (see table below). **API
keys are not bundled with this repo** — without a key, that provider's
endpoint automatically falls back to mock/static data instead of erroring,
so the app still runs, just without live data for that feature.

### 3. Run the dev server

```bash
uvicorn app.main:app --reload --port 8000
```

Visit [http://localhost:8000/health](http://localhost:8000/health) — you
should see `{"status":"ok"}`. Interactive API docs are auto-generated by
FastAPI at [http://localhost:8000/docs](http://localhost:8000/docs).

> If port 8000 is already taken on your machine (common with Docker/WSL
> port forwarding on Windows), pick another free port and update
> `frontend/.env.local`'s `NEXT_PUBLIC_API_URL` to match:
> ```bash
> uvicorn app.main:app --reload --port 8010
> ```

## Environment variables (`.env`)

| Variable | Default | Required | Purpose |
|---|---|---|---|
| `RAILRADAR_API_KEY` | *(none)* | For live tracking | [railradar.in](https://railradar.in/) |
| `OPENWEATHER_API_KEY` | *(none)* | For live weather | [openweathermap.org/api](https://openweathermap.org/api) — free tier |
| `OPENTOPOGRAPHY_API_KEY` | *(none)* | For elevation profile | [opentopography.org](https://opentopography.org/) — free registration |
| `CORS_ORIGINS` | `http://localhost:3000` | No | Comma-separated list of allowed frontend origins |

None of these keys ship with the repo, and `.env` is gitignored — never
commit it. All external calls gracefully fall back to mock/static data if
a key is missing, invalid, or the upstream API fails — see `services/` and
`repositories/mock_repository.py`.

## Endpoints

| Route | Description |
|---|---|
| `GET /api/trains/search?q=` | Search trains by name, number, origin, or destination (served from the static database) |
| `GET /api/trains/{id}/status` | Live train position/status via RailRadar, cached 30s, falls back to a time-interpolated static route |
| `GET /api/weather?lat=&lon=` | Current weather for a coordinate via OpenWeather |
| `GET /api/elevation?locations=` | Elevation profile for a list of `lat,lon` points via OpenTopography |
| `GET /api/places?lat=&lon=&radius=` | Nearby rivers/bridges/tunnels/monuments via the Overpass API |
| `GET /health` | Health check |

## Notes

- `app/repositories/data/*.json` holds the static train database and mock
  fallback data, generated 1:1 from the original `frontend/src/data/*.ts`
  files (same train routes, same station coordinates).
- `.venv/`, `__pycache__/`, and `.env` are gitignored — don't commit them.
- CORS is restricted to `CORS_ORIGINS` — update it if the frontend runs on
  a different origin than `http://localhost:3000`.
